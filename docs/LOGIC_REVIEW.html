앱에 구현된 기능마다 코드가 실제로 푸는 식, 알고리즘, 판정 규칙, 허용오차, 가정과 적용 한계를 정리했습니다. 설명을 단순화하지 않았으며, 식과 규칙은 코드에서 옮겨 적은 것입니다. 각 절 끝의 "검토 요청 포인트"는 설계 판단이 들어간 곳, 즉 검토 의견이 가장 필요한 곳입니다.

0.1 범위와 전제

  • 핵심은 정상상태 기본파 dq 판정 엔진입니다(§1–§6). 요구(토크·속도·전압·온도·지속시간)가 이 모델과 데이터로 만족되는지를 PASS / FAIL / UNKNOWN으로 판정하고, 그 근거를 남깁니다.
  • 그 위의 확장 기능(§7–§16)은 열, 전력변환·수명, 효율, PWM·구동계, EMI, 안전·보호, OEW·HEV, 모터 설계, 데이터 계약입니다. 대부분 축약 모델 스크리닝이며, 각 절에 모델 수준과 판정 상한(예: "항상 UNKNOWN", "SCREENING까지만")을 적었습니다.
  • FEA, 스위칭 단위 회로 시뮬레이션, 실기 검증(validation)은 이 앱의 범위가 아닙니다. 수치 예시는 모두 합성(synthetic) 기준 모델 값입니다.
  • 코드 위치 file.py:N은 빌드할 때 소스에서 찾아 넣었습니다. 찾지 못하면 빌드가 실패하므로, 모든 참조는 이 커밋의 실제 정의를 가리킵니다. 수치 예시도 이 커밋의 앱으로 직접 계산했습니다.

0.3 판정 어휘와 여섯 가지 원칙

모든 claim은 상태(FEASIBLE / INFEASIBLE / UNKNOWN), 사유(reason), 근거 종류(evidence), 한정어, 범위를 가집니다. 요구 판정은 이를 PASS / FAIL / UNKNOWN으로 옮기며, 이 매핑은 §3.7에 있습니다. 전체 어휘는 부록 B에 있습니다.

문서 전체에 걸친 원칙
  1. UNKNOWN은 FAIL이 아닙니다. INFEASIBLE에는 증명(필요조건, 정확 열거, 인증 한계)이나 선언 모델 안의 반례가 필요합니다. 탐색에 실패했다고 불가능한 것은 아닙니다.
  2. 누락은 0도, 무제한도 아닙니다. 손실 모델, 한계, 영상분 데이터 등이 없으면 해당 claim은 UNKNOWN(MISSING_INPUT)입니다. 무제한은 명시적으로 선언해야 합니다.
  3. 샘플은 증명이 아닙니다. 연속 범위(전압, 온도, 위상, 각도)의 PASS에는 립시츠 여유, 단조성 증명, 정확 열거 같은 연속 논증이 필요합니다. 없으면 SAMPLED_COVERAGE 한정어나 UNKNOWN입니다.
  4. 외삽하지 않습니다. 맵, 곡선, 표 밖의 점은 평가하지 않고 OUTSIDE_MODEL_DOMAIN입니다.
  5. 경계마다 자기 근거로 판정합니다. 한 경계(예: 효율의 한 제어 체적)의 누락이 다른 경계의 판정을 지우지 않고, 다른 점·온도의 결과를 섞지 않습니다.
  6. 수치 허용오차는 설계 여유가 아닙니다. 경계에 허용오차 안으로 붙은 결과는 ACTIVE나 BOUNDARY_WITHIN_TOLERANCE로 따로 표시하며, 여유로 세지 않습니다.

모든 판정은 하나의 정상상태 기본파 dq 모델(DriveKernel)에서 시작합니다. 이 절은 그 모델이 받는 입력, 쓰는 식, 제약을 분류하는 방식을 코드 그대로 정리합니다. 뒤 절의 모든 기능은 이 커널을 다시 부르며, 식을 따로 복제하지 않습니다.

1.1 좌표계·단위·부호 규약

  • 내부 단위는 SI입니다. 속도 입력 n은 기계 rpm이며, ωm=2πn/60, ωe=pωm (p: 극쌍 수, 양의 정수)입니다.
  • dq 좌표는 진폭 불변(amplitude-invariant) Park 변환이며, d축은 영구자석 자속 방향입니다. dq 전류·전압은 모두 기본파 상(phase) 피크값입니다.
  • Ipk=id2+iq2, Irms=Ipk/2, Vph,pk=vd2+vq2, VLL,rms=3/2Vph,pk. 정지(|ωm|≤10−12 rad/s)에서는 RMS를 "등가 정현파 RMS"로 표시하고, 각 상의 시간 RMS나 정지 열 능력을 추론하지 않는다는 주석을 붙입니다.
  • 전력 부호: Pdc>0은 DC 전원→인버터, Pac>0은 인버터→모터, Pshaft>0은 모터→축입니다. Pshaft=Tshaftωm이므로 역회전 구동(ω<0, T<0)도 Pshaft>0입니다.

단계규칙
적용 가능성과 증거 방향continuous 요구에는 continuous rating만 적용(유한 rating은 결코 통과시키지 않음). 유한 요구 D에는 같은 D의 rating(양방향 증거) 또는 더 긴/continuous rating(양의 증거만: 안쪽 토크는 짧은 시간에도 허용, 바깥 토크는 아무 결론 없음). continuous rating으로 유한 요구에 답하려면 초기 상태가 cold/ambient/equilibrium_at_coolant로 선언되어야 함. 더 짧은 rating은 적용 불가.

3.6 배터리 OCV로 주어진 전압: Thevenin 전원 결합

요구의 Vdc는 기본적으로 인버터 DC 단자 전압입니다(고객 보증 최소 단자 전압에는 이미 전원 강하가 들어 있으므로 다시 빼지 않음). 요구가 배터리 개방전압(OCV)으로 주어지고 Thevenin 전원(Req, 근거)이 선언된 경우에만 단자 전압을 풉니다.

Vinv=Voc−ReqIdc,Idc=Pdc(Vinv)Vinv⇒Vinv2−VocVinv+ReqPdc=0,Vinv=12(Voc+Voc2−4ReqPdc)
  • Pdc가 받는 전압에 따라 정책점이 바뀌므로 Voc에서 시작해 고정점 반복(최대 60회, 10−6 V)으로 풀고, 매 반복마다 정책 해를 다시 구합니다. 상위 근(저전류 쪽)을 운전점으로 택합니다.
  • 모델 무관 한계: 전원이 줄 수 있는 최대 전력은 Voc2/(4Req). 구동 요구의 축 전력만으로 이를 넘으면(Pdc≥Pshaft) 어떤 드라이브도 불가능 → 결합 claim INFEASIBLE(NECESSARY_CONDITION_VIOLATED).
  • OCV나 결과 전류가 전원 모델의 선언 유효 범위 밖이면 OUTSIDE_SOURCE_MODEL → UNKNOWN. 수렴하지 않거나 중간 전압에서 정책점이 성립하지 않으면 NOT_RESOLVED → UNKNOWN.
  • 해가 나오면 요구는 해결된 단자 전압에서 판정되고, FEASIBLE 결합 claim이 AND에 들어갑니다. 해가 없으면 드라이브 쪽은 OCV에서(강하 없음, 낙관적이라고 명시) 보여 주고 결합 claim이 판정을 좌우합니다.
  • 부호 규약: 구동(Pdc>0)은 단자 전압을 낮추고 회생(Pdc<0)은 Voc보다 높입니다. 전기화학 모델은 없습니다.

4.3 병목 진단 (dominance)과 완화 탐색 (relaxation)

"현재 해에서 능동인 제약", "능력을 제한하는 제약", "바꿀 가치가 있는 파라미터"는 서로 다른 개념입니다. 병목은 제약 하나를 조금 완화하고 정책 능력 전체를 다시 계산해서 판단합니다.

  • 기준 정책 능력(61점 스캔, 인증 생략)을 구하고, 선언된 유한 한계마다 +1%(상대) 완화합니다. 한계가 0이면 상대 변화가 정의되지 않으므로 절대 스텝을 씁니다 (전력 1 kW, 전류는 같은 1 kW를 Vdc로 나눈 값, id,min은 −0.01Imax). 미선언 한계는 완화할 수 없고 무제한 한계는 완화가 필요 없습니다.
  • 이득 g=sign·(Tcap′−Tcap), 분해능 ε=2max(10−12Tscale, 10−7Tscale, 10−9) N·m (두 샘플 경계의 이분 허용치). 분류: g>ε limiting, |g|≤ε 단독으로는 제한 아님, g<−ε 비단조 응답, 능력 미확립이면 unresolved(결코 "제한 아님"으로 보지 않음).
  • 쌍 완화: 약한 제약 쌍 중 능동 제약을 포함한 쌍과, 한쪽 방전(또는 충전)의 전력·전류 한계 쌍(항상 함께). 쌍의 이득만 ε을 넘고 어느 단독도 limiting이 아니면 joint bottleneck.
  • 완화 탐색(FAIL 뒤에만): 한계마다 +50%까지(25단계 + 40회 이분) 정책을 FEASIBLE로 만드는 가장 작은 상대 완화를 찾고, 단독으로 안 되면 쌍을 찾습니다. 도중에 UNKNOWN을 만났으면 "증명된 최소 아님"으로 표시합니다.

모든 완화는 진단용입니다. 실제 변경(예: Vdc)은 여러 한계를 함께 움직이므로 sizing으로 평가합니다.

12.1 고장 반응 시간 사슬 vs FTTI

  • 사슬은 사건의 순서(고장 발생 → 감지 → 필터 → 검출 → 확정 → 판단 → 작동 → 안전 상태)이고, 예산 항목은 두 사건 사이 구간의 최소/공칭/최대 지연과 소유자를 가집니다. 주기 태스크는 최악에 한 주기를 더합니다(공칭은 반 주기).
  • 고장에서 선언된 물리적 안전 상태까지 연속된 모든 항목 경로를 열거합니다. 여러 구간에 걸친 항목(예: 시스템 FRTI)은 그 전체에 대한 유효 한계이지만 나눌 수 없습니다. 모든 경로가 실제 반응 시간의 건전한 상한이므로 보장 상한은 경로별 최대합의 최솟값, 최선 하한은 경로별 최소합의 최댓값입니다.
  • 어떤 항목도 덮지 않는 구간(gap), 이어지지 않는 사슬, 같은 구간을 두 항목이 예산하는 중복(합하면 이중 계상)을 보고합니다. 게이트 명령이 드라이버에 도달한 것은 전류 소멸이 아니므로, 끝 사건이 "명령 발행"이면 UNKNOWN입니다.
판정
  • 보장 상한 ≤ FTTI → FEASIBLE(선언 지연이 올바른 상한이라는 가정).
  • 최소합조차 FTTI 초과 → INFEASIBLE(모든 궤적이 느림). 최대값들이 한 궤적에서 함께 일어난다고 선언된 경우(worst_case_attainable) 상한 초과 → INFEASIBLE.
  • 그 외의 상한 초과 → UNKNOWN(BOUND_INCONCLUSIVE). 한 궤적에서는 FHTI = FDTI + FRTI이지만 독립 최악의 경우엔 sup(D+R)≤supD+supR만 성립하므로, 최대합 초과는 실패 증거가 아니라 "선언 한계로는 보장 못 함"입니다.

13.1 임계값 창: 충분조건으로만 판정

단조 스칼라와 무기억 센서에 대해, 공칭 임계값 θnom이 오동작 없음(하한 lo)과 보호(상한 hi)를 함께 만족하는 충분조건은 다음과 같습니다.

lo=xN,max+E++Eθ+rn,hi=B−E−−Eθ−rs,lo<θnom≤hi
  • E±는 센서의 과대·과소 판독 오차, Eθ는 비교기 임계 오차, rn,rs는 선언 여유입니다. 보호 리뷰(§13.3)에서는 E+=|o|+|g||xN,max|, E−=|o|+|g||xlim|로 넣습니다(g 이득 오차, o 오프셋).
  • B는 측정된 트리거 값에 대한 보호 측 물리 한계입니다. 따로 주지 않으면 B=xlim−Δxafter이며, 이 식은 무기억 센서에서만 성립합니다. 센서가 필터를 가지면 이 식을 쓰지 않고 "not_applicable"로 둡니다. 동적 한계를 선언할 때는 상태(valid / no_bound / not_applicable / invalid)도 함께 선언해야 하고, 없거나 무효인 한계를 정적 식으로 대신하지 않습니다.
판정
  • 유효한 B가 없음 → UNKNOWN(BOUND_INCONCLUSIVE): 한계를 보호한다고 보장되는 임계값이 없습니다.
  • lo<hi → FEASIBLE, 창 (lo,hi]와 폭을 보고합니다.
  • lo≥hi이고 한계들이 "빡빡하며 동시에 도달 가능"(tight_attainable)으로 선언됨 → INFEASIBLE: 임계값 조정만으로는 두 요구를 함께 만족할 수 없습니다.
  • lo≥hi인 그 밖의 경우 → UNKNOWN(BOUND_INCONCLUSIVE): 보수적 한계로는 보장하지 못한다는 뜻일 뿐, 임계값이 존재하지 않는다는 증명은 아닙니다.
